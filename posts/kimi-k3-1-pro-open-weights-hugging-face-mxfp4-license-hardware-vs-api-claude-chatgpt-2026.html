What landed on Hugging Face

  • Repo: moonshotai/Kimi-K3.1-Pro — public, not gated. HF API showed 96 model-*-of-000096.safetensors shards plus config/code; total files about 1.56 TB (our sum of the tree listing)
  • Architecture (from the model card): MoE, 2.8T total / 104B active parameters, 896 experts (16 selected per token + 2 shared), 1,048,576-token context, text + image (MoonViT-V2, 401M). Attention mixes Kimi Delta Attention with Gated DeepSeek Sparse Attention on 24 layers
  • Quantization: MXFP4 weights / MXFP8 activations via quantization-aware training. vLLM's recipe notes routed-expert weights are MXFP4 on disk (~1.56 TB); attention, shared experts, and the vision tower stay BF16, with an MXFP4 memory figure of about 1,874 GB for the serving variant
  • Engines with day-0 recipes: vLLM, SGLang, and TokenSpeed (named on the model card). AMD published day-0 support on 8× Instinct MI355X with ATOM and vLLM; Nebius and others announced day-0 hosted inference
  • Cyber note on the card: Moonshot says it removed cybersecurity-related training data for the open-weight release; its internal xdev-bench-hard score is listed at 81.0% (vs 90.5% without that change). Treat those as Moonshot's numbers, not ours

License: open with two commercial guardrails

The file is the Kimi K3.1-Pro License (Copyright 2026 Moonshot AI). In plain terms it is MIT-like for use, modification, redistribution, fine-tuning, and sale, with notice retained, plus:

  • Model as a Service over $20M: if you (and affiliates) operate a business that gives third parties meaningful control over inference or fine-tuning inputs/parameters/training data, and your aggregate revenue exceeds $20 million over any consecutive 12 months, you must sign a separate agreement with Moonshot before commercial use of the Software or derivatives. Embedded product features and mere request-relaying are carved out of that definition
  • Very large products: commercial products or services with more than 100 million monthly active users or more than $20 million monthly revenue must prominently display "Kimi K3.1-Pro" in the UI
  • Those two rules do not apply to: (a) true internal use that does not expose the model's capabilities to third parties, or (b) use through Moonshot's official products or certified inference partners

So a company hosting K3.1 Pro for its own employees is in a different bucket from a startup reselling API access at scale. Read the LICENSE file yourself before you ship.

Hardware: not a laptop model

  • vLLM baseline: simplest working NVIDIA layout is tensor parallel 8 — one B300 node or two GB300 trays (or the equivalent VR200 preview path). Same TP8 shape on one MI355X node for AMD
  • Memory shape: you need on the order of 2 TB-class aggregate high-bandwidth memory for the MXFP4 checkpoint plus BF16 leftovers, KV cache, and runtime. Single H100/H200/B200 cards are not enough; H100-class boxes need multi-node layouts
  • Long context: decode-context parallelism (DCP) is how vLLM stretches KV capacity for 1M-token and multi-session agent work; expect extra host DRAM if you offload KV
  • Practical takeaway: if you do not already rent or own an 8× 288 GB-class node (or a multi-node fabric), self-hosting is a CapEx/OpEx project. The weights being public does not make them free to run

Which to pick

  • Research / fine-tune / internal cluster already paid for: pull the official HF repo, run the vLLM or SGLang recipe, and keep the LICENSE with your deploy docs
  • Ship a product that embeds the model for end users: usually fine under the license's embedded-feature carve-out — still not legal advice; confirm with counsel if you're close to the MaaS or 100M-MAU lines
  • Resell inference at scale: budget for Moonshot's separate agreement once you approach $20M trailing revenue, or use Moonshot's API / a certified partner instead
  • Just need a strong coding agent this month: Kimi Plus ($19) as overflow, Claude Ultra/Max, or ChatGPT Pro remain the low-friction paths. Weights are a hosting story, not a subscription replacement
