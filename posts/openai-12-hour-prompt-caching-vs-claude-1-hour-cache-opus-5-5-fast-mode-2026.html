OpenAI's new 12-hour prompt caching vs Claude's 1-hour cache: when the 2.5x write pays off, plus Opus 5.5 fast mode at $8/$40 (2026)

On Tuesday, Oct 20, OpenAI added 12-hour prompt caching to the Responses API. Codex lead Tibo Sottiaux made it "Day 16" of the 28-day Codex challenge, and his post passed 1.3 million views overnight. The headline numbers from OpenAI's docs: a 12-hour cache write costs 2.5x the normal input price, the default 30-minute write costs 1.25x, and a cache read costs 0.1x (0.05x on GPT-6.1 Sol) whichever lifetime you pick. Anthropic's longest published cache is still 1 hour, at 2x. Separately, Anthropic's API pricing now lists fast mode for Opus 5.5 at $8 input / $40 output per million tokens, 2x the standard price. Below: what each option costs on a real workload, a simple rule for which cache to use, and what changes for people on a Codex or Claude subscription. We read OpenAI's and Anthropic's pricing and caching docs on the morning of Oct 21.

Update, Oct 27: OpenAI released GPT-6.1 Terra on Oct 26, and it gets the same cheap cache reads as Sol (0.05x input). Terra's rates are exactly half of Sol's on every line: $1 input, $0.05 cached, $1.25 for a 30-minute write, $2.50 for a 12-hour write, and $5 output per million tokens (above 272K input: $2 / $0.10 / $2.50 / $5 / $7.50). So every Sol figure in the worked example below halves on Terra: the 100k-token prefix reused 8 times with 75-minute gaps costs $0.29 with the 12h cache vs $0.90 uncached. OpenAI says Terra is built for computer use and writing, and that Sol and Astra "remain the better choice" for the hardest coding. Full comparison: GPT-6.1 Terra at $1/$5 vs Sol, Claude Sonnet/Haiku/Opus 5.5, and Kimi K3.1 Pro.

Quick verdict

Your app reuses the same big prompt (instructions, tools, docs) with gaps over an hour: use OpenAI's 12h cache on that prefix. It beats not caching from the second reuse onward. Claude has no published cache that lasts that long. Requests come every 5–60 minutes: Claude's 1-hour cache (2x write) and OpenAI's 12h (2.5x) both work. On the same $2 input price, Claude Sonnet 5.5 comes out slightly cheaper (example below). Requests come within 30 minutes of each other: OpenAI's default 30-minute cache (1.25x) is enough. Don't pay for 12h. You want Opus 5.5 faster: fast mode is $8/$40 (up to 2.5x faster, per Anthropic). GPT-6.1 Sol's Fast tier is $4/$20, and its Ultrafast tier is $12/$60. You use Codex or Claude Code on a subscription, not the API: none of these per-token prices hit you directly. Codex Plus is $20, Pro is $100 / $200 / $500. Claude Pro is $20 ($17/month annually).

What changed on Oct 20

  • New 12-hour cache lifetime (OpenAI): on GPT-5.6 and later, in the Responses API, set prompt_cache_options.ttl to "12h". You can also set it on one breakpoint with prompt_cache_breakpoint.ttl. The default stays "30m"
  • Prices: 12-hour writes are 2.5x the uncached input price, and 30-minute writes are 1.25x. OpenAI says these are total rates, not surcharges on top of normal input. Reads are 0.1x on most GPT-5.6+ models and 0.05x on GPT-6.1 Sol, for either lifetime
  • "12h" is a minimum, not a guarantee of a hit: OpenAI says the lifetime governs eligibility for cached pricing. It "does not guarantee that every request reuses stored KV tensors or has lower latency." A 30-minute read doesn't restart the 12-hour clock
  • Upgrades aren't credited: moving tokens that already have valid 30-minute coverage up to 12 hours bills a new 12-hour write, with no credit for the earlier write
  • Mix both in one request: put stable instructions and reference material first with a 12h breakpoint, and session context after it with 30m. Each request can create up to four cache writes, and the minimum cacheable prefix is 1,024 tokens
  • Codex and ChatGPT Work: Tibo's Day 16 post says that for logged-in users "across Codex & Work we keep cache forever," so coming back to an old conversation hours later is "guaranteed to hit the cache." OpenAI hasn't published how much that stretches Plus or Pro usage limits

Worked example: a 100k-token prefix reused 8 times in a day

Say your agent sends the same 100,000-token prefix (system prompt, tool definitions, a codebase or policy doc) 9 times in a workday: once to start, then 8 reuses.   • How we got these numbers: 100k tokens costs $0.20 uncached on Sol, $0.25 as a 30-minute write, $0.50 as a 12-hour write, and $0.01 as a read. For Sol 12h, that's one write plus 8 reads = $0.58. With the 30-minute default and gaps over 30 minutes, every request writes again: 9 × $0.25 = $2.25, which is more than not caching. Sonnet 1h = $0.40 + 8 × $0.01 = $0.48. Opus 1h = $0.80 + 8 × $0.02 = $0.96
  • Break-even for 12h vs no cache: at 2.5x for the write and 0.05x per read (Sol), two reuses cost 2.6x the input price against 3x uncached. So 12h wins from the second reuse. At the 0.1x read rate on other GPT-5.6+ models, it's 2.7x vs 3x, so the same rule holds
  • The trap: if your requests are more than 30 minutes apart and you leave OpenAI on the default 30-minute cache, you pay the 1.25x write every time and never get a read. Use "12h" on the stable prefix, or explicit-only mode, which skips the write

What this means if you're on a subscription

  • Codex (ChatGPT Plus $20, Pro $100 / $200 / $500): you don't pay per token. Per Tibo, Codex and Work now keep your conversation cache indefinitely while you're logged in, so resuming an old thread shouldn't cost you a full re-read. OpenAI hasn't put a number on how much further that stretches your 5-hour limits
  • The weekend usage bug: on Oct 20, Tibo said about 40,000 accounts had usage limits that "did not correspond to their actual selected plan." OpenAI says it fixed the problem, is contacting each affected user, and will add credits to their accounts. The amounts going around on X come from user-shared emails, and OpenAI hasn't published them. If your Codex limits drained unusually fast over the weekend of Oct 17–18, check your email
  • Claude Code (Pro $20 / $17 annually, Max from $100): also no per-token billing in the app. If you're on Max and use the $100–$200 monthly API credits, the 1-hour cache and fast-mode prices above are what those credits buy. See our Max API credits breakdown
