What’s new (Cursor Rollouts + Security Review, Sep 23)

  • Rollouts: attaches a monitor to every PR; reports change health per environment — verified healthy / regression detected / inconclusive; Cursor’s take on Firetiger Change Monitors, rebuilt with the Bot Development Kit
  • Monitoring plans: on PR open, writes a PR comment covering risks, intended effect, signals to check, and instrumentation gaps; editable — Rollouts uses your edited version
  • Deploy tracking: wakes on deploy events for the change’s commit; tracks staging vs production separately; compares intended effect plus error/latency signals against pre-deploy baseline
  • On regression: notifies the author; depending on config can open a revert PR for review, pause a progressive rollout, or hand the finding to a cloud agent — does not merge or roll back on its own
  • Integrations: Origin or GitHub for source control; your CD system for deploy events; Datadog and other telemetry (blog also cites Grafana/Honeycomb); feature-flag integration coming soon
  • Security Review / Security Reviewer: runs on every PR (skips drafts); one review comment with exploitable bugs; style/quality stay with Bugbot
  • What it looks for: injection (SQL/command/template/LDAP per blog); authz/authn bypasses including checks a refactor stopped running; secrets; SSRF/unvalidated redirects; unsafe deserialization; vulnerable deps; insecure defaults in infra/config
  • Findings: severity + attack path + proposed fix (blog: one-click fix); dismiss with a reason and it won’t re-raise on that PR; team rules enforceable on every PR
  • Plans & trial: Teams and Enterprise only; enable from the automations tab; next ~10 days include Rollouts usage credits (~50 Teams / ~500 Enterprise)

How to adopt without overbuying

  1. Already on Cursor Teams / Enterprise — enable Rollouts and Security Review from the automations tab; burn the ~10-day Rollouts credits on real PRs before committing to ongoing usage.
  2. Copilot-only shop — stay on Copilot Code Review + Biz/Ent rails unless you specifically lack PR→prod change-health monitoring wired to CD + Datadog/Grafana/Honeycomb; don’t buy Cursor Teams solely for dual-bot headlines.
  3. Claude Code daily driver — keep Claude Pro/Max for Anthropic-native quality/Projects; add Cursor bots only if last-mile deploy monitors are the gap, not because of model-picker or guardrails posts.
  4. Wire integrations before judging — Rollouts needs source control (Origin/GitHub), CD deploy events, and telemetry; without those, verdicts stay inconclusive.
  5. Don’t confuse posts — guardrails (who can approve shell/network) ≠ model picker ≠ Rollouts/Security Review (deploy health + exploitable bugs).
