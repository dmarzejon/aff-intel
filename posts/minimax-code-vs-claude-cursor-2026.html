MiniMax Code vs Claude Code vs Cursor (Sep 2026)

Mid–late September 2026, MiniMax open-sourced MiniMax Code — a terminal coding agent under the MIT license for first-party code. It understands projects, edits files, and runs tests from a CLI (mcode), with an interactive TUI, headless mode for scripts/CI, and Agent Client Protocol (ACP) for editor hooks. That’s a different lane from our Sep 18 Claude Code Projects roundup (coordinator fleets). Here’s when an inspectable OSS harness wins vs paying for Claude Pro/Max or Cursor.

Quick verdict

Want an inspectable OSS terminal harness + BYO models: try MiniMax Code CLI (MIT) — TUI, headless mcode exec, ACP; MiniMax account or bring your own API keys / compatible endpoints. Want Anthropic-native terminal agent quality: stay on Claude Code + Claude Pro/Max — polished product loop, not a DIY fork. Want IDE fleets / Projects / model choice: Cursor — day-to-day shipping, Slack/CI listeners, multi-model IDE agents. Codex / ChatGPT path: fine if your org is already OpenAI-standardized; different UX than Claude Code or MiniMax’s MIT CLI. Do not: treat an OSS CLI as a free replacement for paid model seats — BYO keys still cost tokens, and FrontierHarness-style scores are third-party comparisons with caveats, not a sealed crown.

What’s new (OSS MiniMax Code)

  • MIT open source (CLI): MiniMax published MiniMax Code terminal agent source — first-party code MIT; third-party sandbox/tools/assets keep their own licenses
  • What the source covers: interactive TUI, headless CLI for scripts/CI, and ACP for editor integrations — not the separate MiniMax Code desktop app binary/source
  • Install path reported in coverage: curl -fsSL https://filecdn.minimax.chat/public/install.sh | bash (macOS/Linux/WSL; Windows PowerShell path also mentioned); command mcode
  • Auth: MiniMax login (mcode login / region flags in docs) or BYO API keys and OpenAI-/Anthropic-compatible endpoints
  • Repo: github.com/MiniMax-AI/minimax-code — verify README vs issues-only noise; coverage cites CLI ~v0.4.12 as the MIT drop
  • Benchmarks (attribute + caveat): some write-ups float FrontierHarness Eval figures (e.g. ~76.7% / 23 of 30 on one third-party setup with MiniMax Code + a specific model). Providers, checkpoints, and timeouts differ from other baselines — prefer product facts over scoreboard theater
  • Angle vs Sep 18: that post was Claude Code Projects (coordinator + parallel cloud threads). Today is terminal harness OSS vs Claude Code CLI vs Cursor IDE agents

How to adopt without over-buying

  1. Curious about harness internals — clone/install MiniMax Code CLI, run mcode --help, and poke permissions/tool loops before changing paid seats.
  2. Already on Claude Pro/Max + Claude Code — keep Claude Code for daily Anthropic quality; use MiniMax Code only if you need MIT inspectability or BYO multi-provider in the terminal.
  3. Cursor is already your IDE — stay on Cursor for fleets/Projects; don’t churn for an OSS CLI headline. Add Claude Pro if you want Claude Code’s native loop, not because MiniMax went MIT.
  4. Budget tokens honestly — OSS harness ≠ free inference. BYO keys, MiniMax accounts, Claude seats, and Cursor models all meter usage.
  5. Don’t confuse surfaces — MiniMax desktop app ≠ this MIT CLI drop; Claude Code Projects ≠ terminal harness bake-off; Cursor ≠ a pure CLI clone.
