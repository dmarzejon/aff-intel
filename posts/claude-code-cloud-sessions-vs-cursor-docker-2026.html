Claude Code Cloud Sessions vs Cursor Cloud Agents vs Docker Sandboxes (Sep 2026)

Long agent tasks (hour-plus refactors, overnight test loops) fail on a sleeping laptop. This week’s buyer question is where that work runs — not which frontier model to pick (see our Sep 23 model-picker post) and not PR→deploy bots (see Sep 24 Rollouts / Security Review). Anthropic’s docs now treat Claude Code cloud sessions as a first-class product surface (Pro / Max / Team, plus eligible Enterprise seats). Docker launched Cloud Sandboxes on Sep 24 for agent-agnostic microVM compute. Cursor already sells cloud agents on its own machines. Distinct from our Sep 18 Projects coordinator post: today is session hosting / isolation / laptop-close durability, not fleet orchestration.

Quick verdict

Already on Claude Pro / Max: start cloud sessions from claude.ai/code, the Desktop/mobile Code tab, or claude --cloud; connect GitHub (App or /web-setup) before judging quality. Already shipping in Cursor: keep Cursor cloud agents if you want IDE-native fleets, Origin/GitHub wiring, and model choice inside one editor — don’t buy Claude Pro solely for “cloud” if Cursor agents already cover overnight work. Need agent-agnostic isolation + BYO keys: Docker Cloud Sandboxes (sbx --cloud) with Claude / Codex / Copilot kits — pay-by-the-second compute; local sandboxes stay free. Do not: confuse Projects (coordinator spinning many threads) with a single durable cloud session; don’t assume cloud VM hours are free of plan usage — Claude cloud sessions share Pro/Max rate limits with no separate VM fee, while Docker meters compute separately from your model bill.

What’s new (cloud hosting, late Sep 2026)

  • Claude Code cloud sessions: Anthropic-hosted (or org self-hosted) VMs; keep running after lid close; start from browser, mobile, Desktop (Cloud), terminal (claude --cloud), or routines; teleport back with --teleport
  • Claude environments: Default Trusted network allowlist; Custom/Full/None; setup scripts + filesystem cache; Pro/Max API credentials injected outside the VM
  • Claude GitHub paths: Claude GitHub App (enables Auto-fix on PRs) or /web-setup with local gh token; Auto-fix can respond to CI failures and review comments
  • Docker Cloud Sandboxes (Sep 24): same microVM model as local Docker Sandboxes, on Docker-managed compute; sbx move … --to cloud; kits for Claude Code, Codex, Copilot, and more; MCP gateway + secrets proxy
  • Docker pricing: pay-as-you-go by the second; Small default ~2 vCPU / 4 GiB at $0.14/hr; sizes from Micro $0.07/hr to XL $1.12/hr; paused = $0; default TTL 1 hour, up to 24 hours; bring your own model key
  • Cursor cloud agents (baseline): Cursor-managed machines, subscriptions to PRs/Slack/schedules, Projects coordinators — already covered for fleets; use this post when comparing hosting/isolation only

How to adopt without overbuying

  1. Claude Pro / Max daily driver — connect GitHub, start one real overnight task with claude --cloud or claude.ai/code before upgrading seats; confirm org policy allows remote sessions.
  2. Cursor daily driver — keep Cursor cloud agents / Projects unless you specifically need Anthropic Auto-fix or Docker’s multi-agent kits; don’t double-pay for “cloud” headlines.
  3. Security / isolation first — prefer Docker Cloud Sandboxes (or Claude Trusted/Custom network) when agents need long unattended runs with secrets proxying; Plugin4Shell-style plugin risks are a separate supply-chain topic — pin agent versions and restrict marketplaces.
  4. Cost check — Claude: watch rate limits (no VM meter). Docker: watch $/hr × hours × parallel sandboxes. Cursor: watch plan + model usage.
  5. Don’t confuse posts — model picker ≠ guardrails ≠ Rollouts/Security Review ≠ Projects coordinator ≠ this cloud-hosting buy.
